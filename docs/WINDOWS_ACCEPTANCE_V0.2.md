# Windows / VS2026 验收清单 — V0.2

## A. 7 项 P0 回归

1. 用 VS2026 打开 `BatchRenamer.UIPrototype.sln`。
2. 重新生成解决方案。
3. F5。
4. 窗口出现后等待 2–3 秒。

必须满足：

- 7 行文件正常可见，不再长时间空白；
- 静置后 UI 可正常拖动窗口、点击和滚动；
- CPU 不应持续因 DataGrid 自刷新而高占用；
- 底部出现 `预览 x.x ms`。

如果这一项失败，请不要继续 20,000 条测试，直接截：

- 程序主界面；
- VS Diagnostic Tools CPU 图；
- Output 中 Binding Error；
- Call Stack（若调试器中断）。

## B. 规则输入

依次快速输入：

- 基础名称：`旅行照片`
- 前缀：`2026_`
- 后缀：`_精选`

预期：

- 打字期间不冻结；
- 停止输入约 120ms 后预览更新；
- 快速连续输入时旧 Preview generation 被取消，不出现明显反复闪烁。

## C. 顺序 / 编号

1. 选中第 2、3 行；
2. 点击上移/下移；
3. 拖到不同位置；
4. 使用名称排序；
5. 撤销排序。

预期：

- 当前视觉顺序与编号保持一致；
- 不出现行重复或丢失；
- 操作后 Preview 重新计算。

## D. 参与改名

- 单独取消一行 Checkbox；
- 再点击表头 Checkbox 切换全体。

预期：

- 不再出现 V0.1 的卡死；
- 单行操作只调度 Preview；
- 全体操作结束后只进行一轮 Preview。

## E. 20,000 条压力测试

按 `Ctrl + Shift + T`。

观察：

- 数据装载完成后窗口仍可操作；
- 滚动 DataGrid；
- 修改基础名称；
- 搜索 `IMG_001`；
- 打开/关闭“只看问题”；
- 执行名称排序。

记录：

- 底部 Preview latency；
- 是否明显长时间冻结；
- 内存大概范围；
- CPU 是否在操作结束后回落。

按 `Ctrl + Shift + D` 恢复 7 条数据。

> V0.2 的 20,000 条是架构压力检查，不是最终性能 Gate。最终 Gate 会在 Core / Validation 分层完成后另行冻结。
