# Windows 实机验收 — V0.4

> 本版“执行重命名”仍为禁用状态。所有测试均只读。

## A. 回归

1. VS2026 打开 `BatchRenamer.UIPrototype.sln`。
2. 重新生成解决方案。
3. F5。
4. 7 条演示数据应正常显示、不卡顿。
5. `Ctrl + Shift + T` 加载 20,000 条合成数据：UI 应保持可操作。
6. 搜索、只看问题、拖动、编号、大小写继续正常。

## B. “替换与大小写”可理解性

- 查找：`IMG_`
- 替换成：`Photo_`
- 原名称模式选一个保留原名的选项。

应可直观看到 `IMG_001 → Photo_001` 一类效果。

## C. 文件名合法性

用临时测试文件导入后：

1. 关闭连续编号。
2. 基础名称输入 `CON`：应出现“名称无效”，Tooltip 应说明 Windows 保留名称。
3. 基础名称输入 `A?B`：应出现非法字符错误。
4. 基础名称清空且“不保留原名称”：应出现空主名称错误。

## D. 批次重复目标

导入两个扩展名相同的文件，关闭连续编号，统一基础名称。

两个项目均应显示“目标重名”。

## E. 外部目标占用

在同目录准备：

- `A.txt`（导入）
- `Existing.txt`（不要导入）

关闭编号，把 `A.txt` 的候选主名称设成 `Existing`。

应显示：`目标已存在`。

## F. 未参与对象占位

同目录导入 A/B，取消 B 的参与状态。使 A 的目标与 B 当前名称相同。

A 应被 `TARGET_EXISTS` 阻止，因为 B 不会进入 VacatingSourceSet。

## G. 源对象消失

导入一个临时测试文件后，在 Explorer 中删除该文件，再修改任一规则触发新一轮预览。

应显示：`源已丢失`。

## H. FileIdentity 变化

1. 导入 `A.txt`。
2. 在 Explorer 删除 `A.txt`。
3. 新建另一个同名 `A.txt`。
4. 修改任一规则触发预览。

若文件系统能提供稳定 FileIdentity，应显示：`源已变化`。

## I. Parent / Child

同时导入一个文件夹及该文件夹内部的文件，并让该文件夹产生改名候选。

应出现：`父子冲突`。

## J. Core SmokeTests

运行 `BatchRenamer.Core.SmokeTests`，应覆盖：

- 全大写 → 单词首字母大写；
- 非法字符；
- Windows 保留名称；
- duplicate target；
- A↔B 交换允许；
- 外部目标占用阻止；
- 未勾选占用者阻止；
- case-only rename 允许。
